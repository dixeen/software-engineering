# Аналіз безпеки та технічного боргу (Game Diary)

## 1. Контекст системи
* **Продукт:** Game Diary (мобільний клієнт на Flutter).
* **Користувач:** Геймери, які хочуть вести облік пройдених ігор та нотаток.
* **Дані:** Назви ігор, текстові замітки, статус проходження.

## 2. Чекліст безпеки та ризики (OWASP Top 10)
Виявлено наступні 5 потенційних ризиків:
1. **Broken Access Control / Auth Failures (Високий ризик):** Наразі в додатку відсутня авторизація. Будь-хто, хто візьме пристрій, має доступ до записів. 
2. **Injection / XSS (Середній ризик):** Текстове поле (замітка до гри) приймає будь-який ввід без санітизації. Якщо дані будуть відправлятися на сервер, є ризик XSS-ін'єкцій.
3. **Security Misconfiguration (Низький ризик):** Відсутність глобального обробника помилок; додаток може "впасти" (crash) при непередбачуваних діях користувача.
4. **Security Logging and Monitoring Failures (Низький ризик):** Жодні дії користувача (натискання, помилки) не логуються, що ускладнює відстеження багів.
5. **Insecure Design (Середній ризик):** Дані зберігаються лише в оперативній пам'яті (State). При перезапуску додатка всі нотатки втрачаються.

## 3. Технічний борг
* **Код:** Увесь UI (головний екран і екран деталей) знаходиться в одному файлі `main.dart`. Це ускладнює масштабування.
* **Тести:** Відсутні unit-тести для перевірки зміни стану (вибір гри зі списку).
* **Дані:** Список ігор жорстко закодований (hardcoded) у вигляді масиву рядків, замість використання окремої моделі даних.

## 4. План погашення на 1 ітерацію
**Що виправляємо зараз (в поточному спринті):**
* Провести рефакторинг коду: винести `MainScreen` та `SecondScreen` у різні файли (папка `lib/screens`).
* Видалити дублювання відступів (вже частково виконано в попередньому Code Review).

**Що свідомо відкладаємо (на майбутнє):**
* Підключення локальної бази даних (SQLite / SharedPreferences) для збереження нотаток.
* Впровадження системи логування та екрану авторизації.
